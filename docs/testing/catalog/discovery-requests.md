# Discovery and requests

Release-day journeys against real TMDB/Trakt and real arr instances. Search behavior, availability computation, request policy, and approval contracts are proven by the hermetic suites.

Use the [run template](../run-template.md) to record executions of these cases.

## Discovery against live providers

- [ ] `DISC-001` · P0 · UI/LIVE — Load actual dashboards: movie spotlight, the headline row, In Theaters, Top Rated, Coming Soon, Most Anticipated, Downloading Soon, Recently Downloaded; series spotlight, the headline row, Airing This Week, Top Rated, Coming Soon, Most Anticipated, Recently Downloaded, Airing Next. Verify identity/image/date/status/detail target, and that every discovery row except the headline keeps loading when scrolled to its end without repeating a title (with English-only on, Top Rated is the row most likely to skip a thinned page). Open See all on the headline row and on Top Rated; verify each grid begins with the row's own titles, continues past them without repeating one, and carries the same Available / Requested badges.
- [ ] `DISC-007` · P0 · UI/LIVE — Move a title through unavailable, requested, downloading, partial, and available outside Cantinarr; verify search/detail chips converge over webhook/WebSocket/refetch with requester vocabulary only.
- [ ] `DISC-009` · P1 · LIVE — Against a real Chaptarr, download one book and side-load another that only a rescan discovers; verify both reach Recently Added within one refresh, covers render, and an eBook and Audiobook of the same title appear as two cards ordered by when each file landed. Against a real title with one format on disk and the other genuinely monitored: verify the card reads Requested while the second format is still fetching, flips to Available once it lands, and reads Partial for a title whose second format was never requested — and that the subtitle names both formats' state in eBook-then-Audiobook order.
- [ ] `DISC-017` · P1 · LIVE — With Trakt configured, load trending, popular, public lists/items, calendar, anticipated, and recommendations; verify IDs/media types bridge to usable details.
- [ ] `DISC-018` · P1 · UI/LIVE — Against a real server with a configured Chaptarr instance, open the Books discovery tab and type a term into the **top** search bar that matches both an owned title and an un-owned one; verify results float over the browse rows, an owned row shows its cached library cover while an un-owned row stays iconic, each row carries its per-format ownership summary, and tapping one opens the book detail carrying the search term.
- [ ] `DISC-019` · P1 · UI/LIVE — With **two** Chaptarr instances configured and genuinely different libraries, search on one, then switch the active instance from the shell; verify the first library's results disappear and the second library's results for the same term take their place — never a merge, never a stale row under the new instance's name.
- [ ] `DISC-020` · P1 · UI/LIVE — As an admin, revoke a test user's book-library access grant (see [`docs/books-setup.md`](../../books-setup.md)); as that user, search from the Books tab top bar and verify the message names the access problem rather than the generic connection failure, and that it names no instance, host or admin.
- [ ] `DISC-021` · P1 · UI/LIVE — Against a real server with **both** the AI assistant service enabled and a Chaptarr instance configured, search from the Books tab top bar using a phrase the assistant heuristic would claim (`books like …`, `authors like …`, and a term ending in `?`), then an ordinary title; verify every one of them returns book results in the overlay with no "Ask AI" takeover covering the page — and that tapping the **Ask AI** pill still hands the typed text to the assistant.
- [ ] `DISC-022` · P1 · UI/LIVE — Against the same AI-plus-Chaptarr server as `DISC-021`, open the Books discovery tab, type a question ambiguous between media types (`what's good right now?`), reach AI mode via the **Ask AI** pill (the only route in on Books) and send; verify the reply is about books and authors, not movies or TV, and that the chat bubble shows exactly the question as typed with no added framing words. As a contrast, ask the identical question from the Movies tab and verify that reply is not book-flavored — proof the Books answer came from the tab context, not the model's defaults.
- [ ] `DISC-027` · P1 · UI/LIVE — Against a real server with the AI assistant enabled and a Lidarr instance granted to the signed-in user, search from the Music tab top bar for an artist and for an album, then reach AI mode via the **Ask AI** pill and ask for something to listen to; verify the album results open the album detail with external cover art, the assistant's reply is about albums and artists (not movies), a request made through the assistant adds the artist with only that album monitored, and that a user without a Lidarr grant gets the assistant's "music is not available for this account" answer rather than a search.
- [ ] `DISC-028` · P1 · UI/LIVE — Against real TMDB with English-only on, open the Movies tab's Browse by genre strip, choose a genre, then Filters: add a second genre, a 2010 to 2019 range, and rated 7+, and sort by Top rated; verify every page arrives full of English-language originals, no one-vote title leads the rating sort, the Filters button counts three groups, Clear filters restores the unfiltered browse, and a `/browse/movie/discover?genres=28` link opens the same grid on web. Then switch the headline source between Trakt trending and TMDB trending under Settings > Discovery and open the headline row's See all each time; verify the grid retitles after the source that answered and keeps loading past the row.
- [ ] `DISC-029` · P1 · UI/LIVE — Against real TMDB on a device whose locale country is not the US, open Browse Movies and Filters; verify the Streaming on section opens on that country with its own services and logos, that switching the region swaps the service list, that a keyword and a studio typed into their fields are suggested after a pause and added as removable chips, and that an empty result names the language, service, keyword, and studio in words. Apply a language plus a service and open the same `/browse/movie/discover?lang=…&prov=…&region=…` link on web; verify it reproduces the grid and its empty state names the service, not its id.
- [ ] `DISC-030` · P1 · UI/LIVE — Against real TMDB with English-only on, open the TV tab's Browse by genre strip and choose a genre; verify the grid is a TV grid (an All shows chip, episode-count subtitles on partial series), that Newest sorts by first air date, and that a `/browse/tv/discover?genres=18` link opens it on web. Back on the tab, verify Coming Soon shows only series premiering in the next three months (no returning season of a show already airing), Airing This Week shows series with an episode this week, and See all on Top Rated keeps loading past the row.
- [ ] `DISC-031` · P1 · UI/LIVE — Against real TMDB, open a well-known movie (The Matrix) and a show (Breaking Bad). Verify the Cast row shows the billing with photos, a face opens that person's sheet, See all lists everyone credited with the crew grouped by department (a show's creators first), and the Details lines (directed by, written by, studio chips, country, runtime, budget, revenue; created by, network and status for the show) match TMDB's own page for that title. Tap a studio chip and verify a grid titled after the studio opens. On a device whose region is not the US (or a browser whose language carries a country), verify the movie's Release dates section is headed by that country and shows its dates, falling back to US only when TMDB has none for it. Open an unreleased movie and verify a Status line leads its Details. Tap each Links chip (IMDb, TMDB, Trakt) and verify the title's own page opens on that site outside the app. Open a library book's page and verify its Links chips open that book's own page on Goodreads (the edition Chaptarr tracks) and Open Library outside the app, and that a Hardcover chip appears only when Chaptarr's metadata lists a hardcover.app link for the book; a lookup result carrying no provider ids shows no Links line.
- [ ] `DISC-032` · P1 · UI/LIVE — Against real TMDB and Trakt with a real Radarr and Sonarr, make a test user a kids account from Settings > Users > User settings (US, movies up to PG, shows up to TV-PG, Hide unrated titles on, Horror hidden for movies) and verify Require approval flipped to On before saving. Signed in as that user: verify every Movies and TV row (the headline row on both sources, In Theaters, Top Rated, Coming Soon, Most Anticipated, Airing This Week) shows no title above the caps and no horror, that Browse by genre offers no Horror chip, that a search for a well-known R-rated title returns no such movie while the same search as an adult does, that opening a deep link to that title lands on the plain "This title isn't available on this account." page, that a person sheet for an actor with mature credits lists only the allowed ones, that the Downloading Soon / Recently Downloaded / Airing Next rows show only library titles Radarr and Sonarr certify within the caps (a Radarr set to a certification country other than US reads as unrated and hides everything while unrated titles are hidden — note that rather than failing it), that the assistant asked for "the scariest movie you know" names nothing above the caps and says titles were hidden, and that requesting an allowed title lands in the approval queue. As the admin, promote the account and verify the refusal names the kids account; turn the kids account off and verify the same rows fill back in. Also confirm on Sonarr that `GET /api/v3/episode/{id}?includeSeries=true` embeds `series` (the proxy hides the episode when it does not).
- [ ] `DISC-023` · P1 · LIVE — On a real Chaptarr instance, **signed in as a requester rather than an admin** (admins bypass the arr proxy's read allowlist entirely, so an author lookup an ordinary account cannot reach still answers for them), search the Books discovery tab for an author your library **holds** and one it does not. Verify the held author sorts first, shows `Author · n of m books available`, carries a chevron, and **opens their author page** (this is the case that 404'd: Chaptarr's `AuthorResource.ForeignAuthorId` is derived by provider priority, so a library record can report `gr:…` while a fresh metadata lookup reports `hc:…` for the same person — resolution is by normalized name, and the link must use the *library* record's id). Verify the unheld author reads `Author · not in your library`, shows a magnifier rather than a chevron, and that tapping it puts their name in the toolbar and lists their books as requestable rows.
- [ ] `DISC-024` · P2 · LIVE — With the Books discovery tab searching normally, make the author lookup fail on its own (block `/api/v1/author/lookup` at the proxy, or point the instance at a Chaptarr build without it) while `book/lookup` still answers. Verify the book rows still render, the overlay says "Authors could not be searched.", and none of the three book failure messages appear — an author section that could not be read must never render as one that matched nobody.
- [ ] `DISC-025` · P2 · LIVE — With a library holding two distinct author records whose names differ only by punctuation or spacing (e.g. `Ursula K. Le Guin` and `Ursula K Le Guin`), search that name. Verify both rows render, neither is openable, and both say two authors share the name — no record is silently chosen. If your library has no such pair this case is not runnable; note that rather than passing it.
- [ ] `DISC-026` · P2 · LIVE — On a large library, confirm the first Books-tab search of a session is not noticeably slowed by the author-resolution fetch (`GET /author`, one unpaginated response per instance, held until the library changes). If it is, that fetch is the thing to make cheaper — Chaptarr's `library/search` is the indexed alternative, but it returns no `foreignAuthorId`, so using it needs a server-side numeric-id resolution path.
