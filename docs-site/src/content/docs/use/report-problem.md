Open the affected title and use **Report a problem** when it is available. Reporting may depend on server policy, the title's state, and whether you already have a report for that library.

## Say what you expected and what happened

Useful reports include:

- “Season 2 episode 4 plays the previous episode.”
- “The movie has no English audio track in Plex.”
- “The audiobook stops halfway through chapter 6.”
- “The title says Requested, but the request has shown a connection error since yesterday.”

Include the affected season or episode, book format, selected library, and playback app. If playback fails, copy the actual error message. Do not include passwords, connect links, provider tokens, or service API keys.

## Follow the thread

Keep related details in the existing report. An administrator or the configured agent may ask a follow-up question. Answering it can be more useful than opening a second report.

Cantinarr may first watch a download for recovery before escalating it. A quiet issue does not mean the report disappeared. The issue's state and timeline explain whether it is being observed, investigated, or waiting for someone.

## After it is marked resolved

Check the actual title again. A repaired import should be checked in the library and playback app. If the same problem remains, reply with what still fails. Administrators can reopen eligible resolved reports.

## If there is no report button

The administrator may have disabled reporting, or the current screen may not yet have enough title or library information to attach the report. Use the household's normal support channel and include the title and exact symptom.

A general Cantinarr application bug belongs in a project bug report after your administrator has gathered versions and reproducible steps. See [getting help](/troubleshooting/get-help/).
